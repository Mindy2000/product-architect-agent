# Product Architect Agent：当前状态与固定验收边界

更新：2026-11-14。工程版本 0.6.0，后续修复尚未正式发行。本文件是当前状态入口；历史阶段说明只说明当时的实现与证据，不代表当前版本已经通过全部验收。

## 产品范围

个人本地中文应用开发工作台，无账号系统。统一调度协调规划、开发、审查测试三个专业智能体：确认需求和验收标准 → 规划 → 受控代码修改 → 隔离构建与 Playwright → 有限自动修复 → 交付、Trace、Git diff 和源码导出。SQLite checkpoint 支持暂停和恢复；`completed` 表示执行完成，逐条需求验收另行绑定当前源码。

- 生成 React/TypeScript/Vite/Tailwind，最多 12 页、128 个受控文件、单文件 64 KiB、源码总计 2 MiB；支持 localStorage 或固定 FastAPI/SQLite CRUD 与附件，不开放任意后端或命令。
- DeepSeek 和千问文字通道可按角色选择；千问视觉是另一个显式调用通道，各自受许可和费用上限约束。两个供应商不保证消除共同误判。
- 支持 TXT/MD、PDF/Office 文字提取、按需本地 OCR、切片和全文检索；本地全文检索不是 Embedding 语义检索。Dify 是可选接口，核心开发路径不依赖它，当前暂停远程使用和验收。
- 支持增量维护、规则、协作资料、版本比较、逐条验收、本地视觉对照、固定响应评测、源码定位候选与执行记录回放。回放不重放真实模型或业务数据库副作用。
- 支持业务数据/附件与整套工作台备份恢复、并排升级、脱敏诊断和首次使用向导。恢复创建独立副本，保留费用历史；工作台备份不包含密钥。

## 已有证据与尚未完成的验证

最近一轮真实复测使用 DeepSeek 规划/开发与千问审查：CRUD 和本地资料任务的原冻结独立功能检查均为 4/4，完整自主闭环为 **1/2**。资料任务完成；CRUD 在最后审查提交时停止，不能算自主通过。共 55 次文字请求，估算 ¥1.4016834，无视觉或 Dify 请求。历史失败记录不改写。

此后已修复审查正文分配、可引用证据清单、最后两步动作格式反馈及具体失败原因保留。此前 389 项 Python 回归、历史响应回放和两组固定响应容器流程通过。离线修复通过不能替代一次新的真实 CRUD 自主复测，也不能推出任意需求的成功率。

本轮仅补齐统一自动测试入口及发行说明，再冻结候选文件进行离线验收。新增固定响应场景覆盖交互检查失败后修复、末步错误提交后纠正、持续错误按原限额停止。最新结果以对应候选文件 SHA256 与本地验收回执为准；不把旧版 CI 通过状态当作本轮通过。

## 固定收尾清单

| 项目 | 本轮安排与通过标准 |
|---|---|
| 统一回归 | Python、前端测试、格式、类型、界面构建均通过 |
| 离线完整流程 | `scripts/offline_quality.py` 的 12 组固定场景全部通过，包含修复、停止、checkpoint 和审查提交 |
| 故障与费用保护 | 复用自动回归验证预算、取消、超时、格式错误，不增加远程调用或放宽限额 |
| 数据安全与恢复 | 合成资料验证数据库/附件/费用/checkpoint 保留、独立恢复及升级；不恢复真实用户资料 |
| 隔离与交付 | 权限、路径和密钥保护，构建/测试证据与源码一致，发行清单和公开文档链接可校验 |
| 干净安装 | 从冻结源码/预构建 macOS ZIP 在新目录安装、启动停止、并排升级；复用已安装的系统工具与固定容器镜像 |
| 最后真实复测 | 只剩 1 次 CRUD；开始前单独说明费用上限并获确认，沿用冻结需求与独立测试，失败不自动另开任务 |

不扩展功能、不重复完整付费矩阵。Dify 远程验收和 Windows 完整运行不做；正式发行与 GitHub 同步暂不进行。Windows 构建配方保留，但本轮不构建、不验证，也不将其宣称为已验收支持。
