# 0.3.2 审计修复与有限优化

日期：2026-11-07。用户授权范围仅为审计三项问题、两项维护问题，以及上下文、验收覆盖和维护结构优化。当前总状态仍以 PROJECT_STATUS.md 为准。

## 修复

1. 最近工具结果从新到旧分配额度，再按时间顺序展示，旧内容被省略时明确标注。最新报错不会再被旧文件读取耗尽额度；长日志保留末尾，文件片段保留读取偏移、校验值和明确截断说明。
2. 模型返回缺失、不完整或非法用量时，保留原始预留金额，actual_cny保持空，状态usage_missing。格式错误、重复回执和后续预算检查均保留这笔预留，不假设固定12000输入Token。
3. 项目选择与后台记录更新分离；请求序号、选择修订、流式事件共同阻止旧回复覆盖新项目。恢复操作不再启动与事件流竞争的轮询循环。新建任务和卸载使旧请求失效。
4. 验证结果绑定实际镜像ID、当前框架文件、安全配置和固定执行代码。构建/测试使用核对过的不可变镜像ID，运行前后再次核对；旧回执缺指纹、镜像变化或环境不可核对时不能作为当前通过证据。验收确认同时绑定运行环境。不会删除历史证据或自动运行真实项目。
5. 发行说明改为同版本或明确兼容的升级路径；0.2.0/0.3.0/0.3.1可升级、恢复到0.3.2，未知版本与降级仍拒绝。

## 三项优化

- 上下文：最新工具内容最多22000字符、词法文件索引最多6000字符、完成任务摘要最多2000字符；这三部分的主体共享原30000字符额度，元信息另计，既有规格和清单仍保留。索引仅扫描受控源码，提供有限符号和导入提示，不是语义分析，不调用额外模型，也不提高权限或项目规模。真实成功率及费用改善暂未测量。
- 验收：固定检查遍历已确认静态Hash路由和首页，在桌面/手机宽度使用独立浏览器状态，检查挂载、未捕获错误、横向溢出、刷新及基本Tab焦点。参数路由需要实际数据，明确列为待核对。空数据提示、业务错误恢复、页面实际内容、视觉和完整无障碍仍需独立测试或人工确认，不自动记作需求通过。新增合成独立场景验证空状态、非法输入/恢复、键盘提交和持久化，并故意制造第二页溢出来证明固定检查能拦截。
- 维护结构：所有前端面板共用本机API地址与无自动重试的网络传输；核心请求和部分面板复用JSON错误处理，运行数据类型、选择控制与React状态逻辑拆出。前端源文件统一格式，并在CI检查；Prettier仅为锁版开发依赖，不进入生成应用的运行依赖。

运行：`python -m unittest discover -s tests -v`、`npm run test:frontend`、`npm run format:check`、`npm run typecheck`、`npm run build`。空闲工作台停止后，`python scripts/offline_quality.py --output outputs/optimization-offline`执行六组离线流程。具体结果以本轮日志和GitHub最终CI为准。

旧交付包仍保留交付时快照。升级后旧记录若没有运行环境指纹，会显示无有效当前验证证据；这不是删除原交付，也不会自动触发付费重跑。真实任务、Windows完整验证与正式Release继续暂缓。模板、可视化选中编辑、文件保护和按阶段模型选择没有实施。
